⬡ fact_daily_activity fact

The central fact table. Grain: one row per engineer per day. Contains the only true measure in this schema — contributions count — plus foreign keys to dim_engineer and dim_date.

COLUMNS · 4
activity_id PK
Surrogate key for the activity row.
engineer_id FK
References dim_engineer. Identifies whose activity this is.
date_id FK
References dim_date. The calendar day of the activity.
contributions
Number of GitHub contributions on this day. The one measurable fact.
⬡ dim_engineer dim

Dimension holding personal attributes of the engineer — who I am. Name and role are stored here and used to filter queries across all marts.

COLUMNS · 3
engineer_id PK
Unique identifier for the engineer.
name
Engineer's name. Used in WHERE clauses to filter rows.
role
Job title or role (e.g. Analytics Engineer).
⬡ dim_date dim

Date dimension. Gives the fact table its time axis. Enables filtering and grouping by year, month, or day of week without date arithmetic in the query.

COLUMNS · 5
date_id PK
Surrogate key for the calendar day.
date
The actual calendar date (DATE type).
year
Year extracted from the date.
month
Month number (1–12).
day_of_week
Day name (e.g. Monday). Useful for weekly pattern analysis.
⬡ dim_skill dim

Skill dimension. Each row is one skill belonging to an engineer. Joined directly to dim_engineer — not through the fact table — making mart_skills a pure dim-to-dim query.

COLUMNS · 5
skill_id PK
Unique identifier for the skill.
engineer_id FK
References dim_engineer. Ownership of the skill.
skill_name
Name of the skill (e.g. dbt, SQL, Python).
category
Skill category (e.g. Analytics Eng, Programming).
proficiency
Proficiency level (expert / proficient).

Writing platform dimension. Tracks where I publish articles. Joined to dim_engineer directly — mart_writing is a dim-to-dim query with no fact table involved.
